Remindly — Buy tab becomes Lists first, then items inside each list

Your request: the Buy tab today drops item cards straight onto one screen. Instead, you first create Lists (Groceries, Monthly stock, Birthday party…) and then add items inside a list. The frames below show every screen that changes, followed by the behaviour changes, the data model, and the questions I need answered before building.

Today (v2.10)
Buy tab→All item cards (grouped by group / shop / date)→Quick-add item
Proposed (N48)
Buy tab = Lists→Tap a list→Items of that list→Quick-add into that list

Summary

  • The Buy tab opens on Lists; tapping a list shows only its items, and anything added there belongs to that list.
  • Create (L2), options (L5), delete with a safe default (L6), move items between lists (L8), and restart for repeat trips (L12).
  • Buy Now, checkout calculator, cheapest-shop hints, gestures, Personal PIN and dark mode all keep working, scoped to the list.
  • This reverses the N45 rule "no parallel lists entity", because empty lists are impossible when a list is just a name on an item. Recommended: a small synced ShopList registry.
  • Your current groups become lists automatically on upgrade; ungrouped items wait in Unsorted.
  • Round 2: every list has a Share icon (preview + options) and a dedicated WhatsApp icon (one tap), both sending List_Name:- + numbered Item - Qty / Type - Urgent - Bought lines.
  • Nothing is built. Reply with changes or answers to F1–F11.
